# 코드 리뷰 기준

## P0: 반드시 고쳐야 하는 문제

- 컴파일이 되지 않는다.
- 요구사항의 핵심 기능이 동작하지 않는다.
- 모든 로직이 한 클래스에 몰려 있다.
- 유효하지 않은 상태를 객체가 허용한다.
- 예외 상황에서 프로그램이 의미 없이 죽는다.

## P1: 취업 코드로 가려면 고쳐야 하는 문제

- 필드가 불필요하게 `public`이다.
- getter/setter가 습관적으로 모두 열려 있다.
- `Service`와 `Repository`의 책임이 섞여 있다.
- `Optional.get()`을 바로 호출한다.
- `null` 체크가 여기저기 흩어져 있다.
- 중복 로직이 반복된다.
- 메서드 이름이 의도를 설명하지 못한다.

## P2: 더 좋은 코드로 다듬을 문제

- 메서드가 너무 길다.
- 변수명이 모호하다.
- 컬렉션 선택 이유가 약하다.
- Stream을 억지로 사용했다.
- 테스트하기 어려운 구조다.
- 나중에 DB/JPA로 옮기기 어렵다.

## 좋은 제출의 기준

좋은 코드는 화려한 코드가 아니다.

좋은 제출은 아래를 만족한다.

- 요구사항을 빠짐없이 만족한다.
- 책임이 분리되어 있다.
- 잘못된 입력을 예상한다.
- 이름만 읽어도 의도를 알 수 있다.
- 본인이 직접 설명할 수 있다.

## 리뷰 후 행동 규칙

리뷰를 받으면 아래 순서로 수정한다.

1. P0부터 고친다.
2. 같은 실수가 다른 파일에도 있는지 찾는다.
3. 수정 후 다시 컴파일 또는 테스트한다.
4. 무엇을 왜 고쳤는지 3문장으로 기록한다.

리뷰는 혼나는 시간이 아니다. 실무자의 눈으로 코드를 다시 보는 훈련이다.
