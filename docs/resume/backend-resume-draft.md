실제 서비스에 필요한 인증, 권한, 데이터 저장, 캐싱, 중복 요청 방지, 테스트, 배포, 운영 확인까지 직접 구현했습니다.

### 주요 기능

- 회원가입과 로그인 기능 구현
- 로그인한 사용자에게 토큰 발급
- 로그인한 사용자만 Todo API 사용 가능
- 사용자마다 본인의 Todo만 조회, 수정, 삭제 가능
- Todo 생성, 목록 조회, 단건 조회, 제목 수정, 완료 처리, 완료 취소, 삭제 기능 구현
- Todo 제목 검색과 완료 여부 필터 기능 구현
- Todo 통계 API 구현
- 자주 조회되는 Todo 통계를 Redis에 임시 저장해 반복 조회 성능 개선
- Todo가 변경되면 기존 통계 캐시를 삭제해 오래된 데이터 응답 방지
- 같은 Todo 생성 요청이 반복 전송되면 중복 생성되지 않도록 처리
- 공통 에러 응답 형식 정리
- Swagger로 API 문서 확인 가능

- Render에 서버 배포
- 서버 상태 확인 API와 운영 문서 작성

### 문제 해결 경험

**1. 다른 사용자의 Todo 접근 차단**

처음에는 Todo 번호만 알면 다른 사용자의 Todo에 접근할 위험이 있었습니다. 이를 막기 위해 Todo를 조회, 수정, 삭제할 때 항상 현재 로그인한 사용자 정보까지 함께 확인하도록 만들었습니다.

결과적으로 다른 사용자의 Todo 번호를 알고 있어도 조회하거나 수정할 수 없고, 본인의 데이터만 다룰 수 있게 했습니다.

**2. Todo 통계 조회 성능 개선**

Todo 통계는 같은 사용자가 반복해서 볼 가능성이 높은 기능입니다. 매번 데이터베이스에서 개수를 계산하면 불필요한 조회가 반복되기 때문에 Redis에 60초 동안 임시 저장하도록 했습니다.

Todo가 새로 생성되거나 수정, 완료, 삭제되면 기존 통계가 달라질 수 있으므로 해당 사용자의 캐시를 삭제하도록 처리했습니다.

**3. 중복 생성 요청 방지**

사용자가 버튼을 두 번 누르거나 네트워크 문제로 같은 요청이 다시 전송되면 Todo가 중복 생성될 수 있습니다.

이를 막기 위해 요청마다 고유한 중복 방지 키를 받을 수 있게 했고, 같은 사용자가 같은 키로 다시 요청하면 두 번째 요청은 실패하도록 구현했습니다.

**4. 배포 후 서버 상태 확인**

서버가 배포된 뒤 정상적으로 동작하는지 확인할 수 있도록 상태 확인 API를 열었습니다. 또한 Render 로그, 환경변수, 데이터베이스, Redis 연결 상태를 확인하는 운영 문서를 작성했습니다.
